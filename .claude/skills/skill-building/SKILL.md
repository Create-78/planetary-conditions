# Skill: Building Skills

How to create effective, reusable skill documents that codify competencies for consistent application.

---

## Core Principle

**A skill document transforms tacit knowledge into explicit, repeatable guidance.**

The goal isn't to document everything about a topic — it's to give someone enough structure to apply the skill correctly without prior expertise.

---

## When to Build a Skill

Build a skill document when:
- A competency is used repeatedly across projects or team members
- The "right way" to do something isn't obvious and matters
- You find yourself explaining the same approach multiple times
- Quality varies significantly depending on who does the work

Do NOT build a skill document when:
- The task is simple enough to explain in one sentence
- The approach is highly context-dependent with no generalizable pattern
- Existing external documentation already covers it well (link instead)

---

## The Skill Document Structure

```
1. Title & Purpose       → What is this skill?
2. Core Principle        → The key insight in one sentence
3. When to Use           → Triggers and non-triggers
4. Framework/Process     → The structured "how to"
5. Techniques            → Specific tactics
6. Anti-Patterns         → Common mistakes
7. Examples              → Worked demonstrations
8. Quick Reference       → Cheat sheet for experts
```

---

## The Skill-Building Process

### Step 1: Identify the Competency
- What specific thing do you want people to be able to do?
- What would you call this skill in one phrase?

### Step 2: Articulate the Core Principle
- If someone could only remember one thing, what should it be?
- Test: Does this guide decisions in ambiguous situations?

### Step 3: Define the Boundaries
- When should this skill be used?
- When should it NOT be used?

### Step 4: Extract the Framework
- What are the steps or components?
- What's the structure that makes this repeatable?

### Step 5: Capture Techniques and Anti-Patterns
- What tricks improve execution?
- What mistakes do people commonly make?

### Step 6: Build Examples
- What's a realistic scenario to demonstrate this?
- Can you show good vs. bad?

### Step 7: Compress to Quick Reference
- What's the minimum viable reminder for someone who knows the skill?

## Anti-Patterns

### The Encyclopedia
Trying to cover everything about the topic instead of the specific skill.

**Fix:** Narrow the scope. A skill document is a field guide, not a textbook.

### The Vague Principle
Core principles that sound wise but don't change behavior.

**Fix:** Test with "would decisions be different?" If not, make it more specific.

### Missing Boundaries
No guidance on when the skill applies and when it doesn't.

**Fix:** Always include "When to Use" and "When NOT to Use" sections.

### All Framework, No Examples
Plenty of abstract steps but no concrete demonstration.

**Fix:** Include at least one fully worked example.

### Forgetting the Expert
Only writing for beginners, making the document useless for quick reference.

**Fix:** Include a Quick Reference section for people who just need a reminder.

---

## Quality Checklist

- [ ] **Title** clearly names the competency
- [ ] **Core Principle** would change someone's approach
- [ ] **When to Use** includes both triggers and non-triggers
- [ ] **Framework** is concrete enough to follow
- [ ] **Anti-Patterns** warn about common mistakes
- [ ] **Examples** demonstrate the framework in action
- [ ] **Quick Reference** fits on one screen
- [ ] **Test** — could someone apply this without prior experience?

---

## Quick Reference

### Skill Document Structure
1. Title & Purpose
2. Core Principle (1 sentence)
3. When to Use / When NOT to Use
4. Framework (steps or components)
5. Techniques (3-8 tactics)
6. Anti-Patterns (4-8 mistakes)
7. Examples (at least 1 worked example)
8. Quick Reference (1 screen)

### Core Principle Test
> "Would someone make different decisions after reading this?"

### Anti-Pattern Prompt
> "What does this skill look like when done poorly?"

### Quality Gate
> "Could someone unfamiliar with this skill apply it successfully using only this document?"
