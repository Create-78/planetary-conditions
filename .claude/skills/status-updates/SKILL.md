# Status Updates

Write updates that answer: What happened? So what? What's next?

## Core Principle

**Stakeholders want to know: Are we on track? Is anything at risk? Do I need to act?**

## Structure

```
1. Headline      → Most important thing (one sentence)
2. Status        → On Track / At Risk / Blocked / Complete
3. Progress      → What happened (outcomes, not activities)
4. Next          → What's coming
5. Risks         → What could derail us
6. Asks          → What you need from them
```

## Status Indicators

| Status | Meaning |
|--------|---------|
| **On Track** | Progressing as planned |
| **At Risk** | May miss targets without help |
| **Blocked** | Stopped, need intervention |
| **Complete** | Done |

## Anti-Patterns

- **Activity log** — "Had meetings, wrote code" → Focus on outcomes instead
- **Buried ask** — Put requests in their own section, make them obvious
- **Always fine** — Be honest about risks; stakeholders prefer early warning

## Quick Format

```markdown
## [Project] — Status: [X]

**Headline:** [One sentence]

**Progress:**
- [Outcome 1]
- [Outcome 2]

**Next:** [What's coming]

**Risks:** [If any]

**Asks:** [If any]
```
