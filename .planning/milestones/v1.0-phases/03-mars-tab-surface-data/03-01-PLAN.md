# TanStack Query v5 — already installed (`@tanstack/react-query@^5.100.10`)

Key v5 fields returned from useQuery (used downstream by Plan 03-02):
- `data`              — the parsed MAAS2 payload, undefined until first success
- `isLoading`         — true only on first mount before any data lands (false during background refetches)
- `isError`           — true if the queryFn throws or rejects
- `isFetching`        — true during background refetches (use NOT used in this plan; Plan 03-02 will silently ignore it per D-18)

```js
import { useQuery } from '@tanstack/react-query'

/**
 * useMarsData — TanStack Query hook for the latest Martian sol from MAAS2.
 *
 * Data source: https://api.maas2.apollorion.com/ (no auth; CORS-open; GitHub Pages
 * hosted — may return a wrong Content-Type header, so we parse the response body
 * as text and feed it through JSON.parse manually rather than using r.json()).
 *
 * Cadence: 1-hour refetchInterval. Underlying MAAS2 data refreshes ~once per
 * Martian sol (~24.6 h), so hourly is generous and matches Discussion.md §3.
 *
 * refetchOnWindowFocus: false — hourly background refresh is sufficient; avoiding
 * focus-driven refetches keeps the UI stable when users tab back into the app.
 *
 * Returns the full TanStack Query result object so the consumer (MarsTab.jsx)
 * can read { data, isLoading, isError, dataUpdatedAt, ... } and propagate state
 * to all nine DataCards from a single fetch (per 03-CONTEXT D-01, D-02).
 *
 * No API key required for MAAS2 — VITE_NASA_API_KEY is reserved for Phase 4's
 * DONKI calls.
 */

const MAAS2_URL = 'https://api.maas2.apollorion.com/'
const ONE_HOUR_MS = 1000 * 60 * 60

async function fetchMarsData() {
  // Manual text → JSON.parse to bypass any wrong Content-Type header from
  // MAAS2's GitHub Pages host (per CLAUDE.md and 03-CONTEXT D-04).
  const response = await fetch(MAAS2_URL)
  if (!response.ok) {
    throw new Error(`MAAS2 fetch failed: ${response.status} ${response.statusText}`)
  }
  const text = await response.text()
  try {
    return JSON.parse(text)
  } catch (err) {
    throw new Error(`MAAS2 response was not valid JSON: ${err.message}`)
  }
}

export function useMarsData() {
  return useQuery({
    queryKey: ['mars', 'maas2', 'latest'],
    queryFn: fetchMarsData,
    refetchInterval: ONE_HOUR_MS,
    refetchOnWindowFocus: false,
  })
}
```

Specific requirements (do not deviate):

1. **Use `r.text()` then `JSON.parse()` — not `r.json()`.** This is the MAAS2 Content-Type quirk handling (D-04, CLAUDE.md). A `r.json()` call could throw on a wrong Content-Type header from the GitHub Pages host. The grep verification will fail if `r.json()` or `response.json()` appears anywhere in this file.

2. **`refetchInterval` literal must be `1000 * 60 * 60`** (or stored in the `ONE_HOUR_MS` constant evaluated to that product). Do not use a different unit, do not use a number-of-minutes constant. The grep verification looks for `1000 * 60 * 60` as a literal in the source.

3. **`refetchOnWindowFocus: false`** must be present (D-03). The grep verification looks for the literal `refetchOnWindowFocus: false`.

4. **`queryKey` is `['mars', 'maas2', 'latest']`** — a stable, namespaced key. Future plans (e.g., a v2 sol-selector) would extend with `['mars', 'maas2', solNumber]`, so the `'latest'` discriminator matters.

5. **`throw new Error(...)` on a non-ok response or invalid JSON.** TanStack Query interprets thrown errors as `isError: true`. Do not return `null` or `undefined` on failure — that would surface as `isError: false, data: null` and break the DataCard error branch in Plan 03-02.

6. **Named export `useMarsData`** (not default export). Plan 03-02 will import as `import { useMarsData } from '../hooks/useMarsData.js'`. Default export would force Plan 03-02 to rewrite its import.

7. **No `staleTime` override** — default (0 ms) is fine. The hourly `refetchInterval` is the freshness contract; `staleTime` would only matter for cross-component query sharing, which we do not have on the Mars tab.

8. **No `retry` override** — TanStack Query's default of 3 retries with exponential backoff handles transient MAAS2 failures per D-19.

9. **No `enabled` flag** — the hook should fire on mount. Plan 03-02's `<MarsTab />` only mounts when `activeTab === 'mars'`, so the hook naturally pauses when the tab is hidden.

10. **No console.log, no analytics, no telemetry.** This is a v1 hook.
