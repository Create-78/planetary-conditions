## Layered Z-Order Contract

This phase introduces a new stacking layer. Locked order from bottom to top:

| Layer | Element | CSS Position | z-index | Notes |
|-------|---------|--------------|---------|-------|
| 0 | AtmosphericBackdrop | fixed inset-0 | z-0 | NEW — below StarField |
| 1 | StarField | fixed inset-0 | z-0 | EXISTING — opacity reduced to ~40% |
| 2 | main content | relative | z-10 | EXISTING — unchanged |

StarField currently renders at z-0 with opacity 0.6. Phase 7 inserts AtmosphericBackdrop at the same z-0 layer but rendered first in DOM order (StarField follows it), so StarField paints above the backdrop. StarField opacity is reduced from 0.6 to ~0.4 so both the body image and the star field read together without one washing out the other.

Source: D-09, 07-CONTEXT.md code_context.

| Element | Value | Rationale |
|---------|-------|-----------|
| Backdrop CSS filter — brightness | 35–40% (start at 35%) | D-05: "subtle visible presence"; dial darker if contrast check fails (D-06) |

## Accessibility & Contrast Guardrail

This is a non-negotiable constraint derived from HERO-04 and D-06.

### Targets

| Text role | WCAG Level | Contrast ratio | Enforcement |
|-----------|------------|----------------|-------------|
| Data card body text (white on panel) | AA | ≥ 4.5:1 | Must be verified during execution against the glass panel + backdrop combination |
| Large/bold headings (white on panel) | AA Large | ≥ 3.0:1 | Must be verified during execution |
| Artist's impression label text | AA | ≥ 4.5:1 | White text on `bg-black/50` pill — inherently safe at all backdrop brightnesses |

### Tuning Levers (in order of preference)

1. Reduce backdrop brightness below 35% (toward 25%) — keeps immersion, fixes contrast.
2. Increase data panel opacity from `/30` back toward `/40` or `/60` — still glassmorphic, safer.
3. Add an additional gradient overlay at base of backdrop (darken bottom 60% of viewport).

The executor MUST perform a visual contrast check during implementation. If any data text fails 4.5:1 (body) or 3.0:1 (large), apply the levers above before shipping. Do not assume the specified starting values will pass — verify.

Source: D-06, HERO-04, WCAG 2.1 AA.

## Atmospheric Backdrop Component Spec (AtmosphericBackdrop)

| Property | Value | Source |
|----------|-------|--------|
| Position | `fixed inset-0` | D-09 |
| z-index | `z-0` (below StarField in DOM order) | D-09 |
| pointer-events | `pointer-events-none` | Never intercepts clicks |
| aria | `aria-hidden="true"` | Decorative only |
| Image source | Same `src/assets/bodies/mars-1600.webp` / `moon-1600.webp` as hero | D-11: no separate backdrop asset |
| Rendering | CSS `background-image` (not `<img>`) — avoids duplicate DOM image and gives CSS filter control | v2 design spec |
| background-size | `cover` | Fills viewport at all sizes |
| background-position | `center` | Consistent with hero center-crop |
| CSS filters applied | `blur(24px) brightness(35%) saturate(80%)` | D-05, tunable per D-06 |
| Bottom gradient overlay | `linear-gradient(to top, #020617 0%, transparent 40%)` as `::after` pseudo or child div | Anchors viewport bottom; ensures near-black beneath data panel |
| Tab switch behavior | Instant src/background-image swap on activeTab change | D-10: cross-fade is Phase 8 |
| Label | None | D-03: label on hero only |

Note: CSS blur on a full-viewport `fixed` element can cause edge artifacts (blurred content bleeds to viewport edges). Mitigate with `overflow: hidden` on the backdrop container or a small negative margin (`-4px` to `-8px`) to extend the image beyond viewport bounds before blur is applied.

Source: D-05, D-09, D-11; CSS blur edge artifact is a known implementation detail.

## App.jsx Layout Integration

The executor modifies App.jsx to place `<BodyHero>` between the TabBar div and the data panel div, and to mount `<AtmosphericBackdrop>` as a sibling of `<StarField>` (preceding it in DOM order so StarField paints above it).

Locked structure:

```jsx
<div className="relative min-h-screen w-full font-sans text-slate-100 antialiased">
  <AtmosphericBackdrop activeTab={activeTab} />   {/* NEW — z-0, below StarField */}
  <StarField />                                    {/* EXISTING — z-0, opacity reduced ~40% */}

  <main className="relative z-10 mx-auto max-w-6xl px-4 sm:px-6 md:px-8 py-8 md:py-12">
    <header>...</header>

    <div className="mb-8 md:mb-10">
      <TabBar activeTab={activeTab} onTabChange={setActiveTab} />
    </div>

    <BodyHero activeTab={activeTab} />              {/* NEW — in-flow, between TabBar and panel */}

    <div className="rounded-lg border border-slate-800/60 bg-slate-950/30 backdrop-blur-md p-6 md:p-8">
      {/* data panel — translucency slightly increased from /40 to /30; blur md from sm */}
      ...
    </div>
  </main>
</div>
```

Gap between BodyHero bottom and data panel: default Tailwind flow spacing (no explicit margin needed — App.jsx currently uses no explicit gap between these elements; the hero becomes a natural spacer). If visual gap needs adjustment, add `mb-4` (16px) to `<BodyHero>`.

Source: D-04, D-07, D-09; App.jsx line 12–36.
