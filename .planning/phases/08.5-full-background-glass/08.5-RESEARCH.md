# Phase 8.5: Full-Background Hero + Glassmorphic Overlay — Research

**Researched:** 2026-05-28
**Domain:** CSS layout (full-bleed hero), glassmorphism (backdrop-filter), parallax adaptation, React component restructure — no new dependencies
**Confidence:** HIGH

---

## Summary

Phase 8.5 replaces the contained 16:7 framed `BodyHero` with a full-viewport-width hero layer, and moves the data panel into a glassmorphic overlay card. The two Phase 8 motion hooks (`useScrollParallax`, `usePrefersReducedMotion`) are reused unchanged — the primary benefit of going full-background is that 10px of parallax displacement becomes perceptible at full scale.

**Three research questions drive every decision in this phase:**

1. **What layout structure replaces the contained hero?** The current `BodyHero` is an in-flow `aspect-[16/7]` box. The replacement must be a full-bleed layer that doesn't disturb document flow for the data panel sitting below it. The correct pattern is a CSS Grid stacking context on a wrapper element — the hero image and the data panel share the same grid cell, so the image occupies the full layout width without pushing the panel down.

2. **What happens to `AtmosphericBackdrop`?** Once `BodyHero` fills the viewport itself, the blurred `AtmosphericBackdrop` beneath it becomes a depth-layer artifact rather than a meaningful backdrop. The least-disruption path: keep `AtmosphericBackdrop` as a subtle secondary depth effect below the hero (it stays below the hero because its `z-0` is lower), but dial down or disable its blur+brightness filter to avoid fighting the full-res hero layer above. Alternatively, suppress it while the hero is visible. The planner should make this call — both options are low-risk.

3. **What is the correct parallax ref target for a full-background image?** The Phase 8 hook's `baseTransform: 'translateY(-50%)'` was designed for a 200%-tall `<img>` inside a fixed-height container. In the full-background case, the image will be sized with `object-fit: cover` and no explicit height-doubling trick is needed. The `baseTransform` option must be changed (to empty string `''` or omitted) to avoid mis-positioning the image; the parallax displacement is applied as the only transform.

**Primary recommendation:** CSS Grid one-column / two-row stack (hero behind, panel in front), glassmorphic panel using existing Tailwind `backdrop-blur-md` + `bg-slate-950/40` classes (no new values), parallax ref on full-background `<img>` with `baseTransform: ''`, keep `AtmosphericBackdrop` but reduce or hide it under the hero. Zero new npm dependencies.

### Pattern 1: CSS Grid Single-Cell Hero + Panel Stack

**What:** A single-column grid where both the hero image and the data panel are placed in the same grid row/column. The hero fills the cell; the panel sits on top via `z-index`. Neither element uses `position: absolute` relative to the viewport — both are in normal flow.

**When to use:** Any time you want content layers that share the same document-flow space without one pushing the other. Cleaner than a `position: relative` wrapper + `position: absolute` content because the grid cell automatically sizes to the tallest child (the data panel), keeping the hero at least as tall as the panel.

**Example:**

```jsx
// Source: css-tricks.com/positioning-overlay-content-with-css-grid/
// Both hero and panel placed in row 1 / col 1 of the same grid.

<div className="grid" style={{ gridTemplateColumns: '1fr', gridTemplateRows: 'auto' }}>
  {/* Hero: stretches to fill the cell */}
  <div
    className="relative overflow-hidden"
    style={{ gridArea: '1 / 1', minHeight: '60vh' }}
  >
    {/* <picture> layers with object-fit cover */}
  </div>

  {/* Panel: sits on top in the same cell */}
  <div
    className="relative z-10 backdrop-blur-md bg-slate-950/50 border border-slate-700/50 rounded-xl p-6 md:p-8 m-4 md:m-8"
    style={{ gridArea: '1 / 1', alignSelf: 'end' }}
  >
    {/* MarsTab / MoonTab */}
  </div>
</div>
```

**Why not `position: fixed` for the hero:** Fixed positioning removes the hero from document flow entirely. The page would have no height and the glass panel would overlap content below it. Do not use `position: fixed` for the hero image.

**Why not `position: absolute` (wrapper-relative):** This works but requires the wrapper to have an explicit `min-height` or `height`, and the panel can overflow outside the wrapper if it grows taller than the hero. The CSS Grid approach auto-sizes the cell to the tallest child — cleaner.

**Alternative (simpler, also valid):** Use `position: relative` on the outer wrapper with `min-height: 70vh`, the hero as `position: absolute inset-0`, and the data panel as a relative-positioned child with appropriate `padding-top` to clear the hero. This is slightly less elegant but equally correct.

### Pattern 2: Full-Background Image with object-fit cover

**What:** An `<img>` element sized to fill its container while maintaining aspect ratio by cropping. No `height: 200%` trick; no `top: 50%` + `translateY(-50%)` center-crop hack needed.

**When to use:** When the container defines the display area (full-bleed hero cell) and the image must fill it without distortion.

```jsx
// Source: verified MDN object-fit documentation
<img
  ref={isActive ? parallaxRef : null}
  src={asset.png}
  alt={asset.alt}
  className="absolute inset-0 w-full h-full object-cover object-center"
  style={{ willChange: 'transform' }}
  onLoad={...}
/>
```

**CRITICAL difference from Phase 8:** The `style` block no longer needs `height: '200%'`, `top: '50%'`, or `transform: 'translateY(-50%)'`. The `object-fit: cover` replaces the manual center-crop trick. This means the `useScrollParallax` hook must be called with **`baseTransform: ''`** (empty string) — not the default `'translateY(-50%)'`.

### Pattern 3: Glassmorphic Panel — Tailwind Implementation

**What:** A card with a frosted-glass appearance achieved by combining:
- `backdrop-filter: blur(Npx)` — blurs whatever is visible through/behind the card
- Semi-transparent background color — lets the blurred image show through
- Subtle border — defines the card edge visually

**Tailwind classes (verified values):**

| Property | Tailwind Class | CSS Value | Notes |
|----------|---------------|-----------|-------|
| Backdrop blur | `backdrop-blur-md` | `backdrop-filter: blur(12px)` | Readable over photo; `blur-lg` (16px) if more frosting needed |
| Background | `bg-slate-950/50` | `background-color: rgba(2,6,23,0.5)` | Existing palette; bump from `/30` to `/50`–`/60` over photo |
| Border | `border border-slate-700/50` | 1px border at 50% opacity | Defines the glass edge; `border-white/10` is an alternative |
| Rounded corners | `rounded-xl` | `border-radius: 0.75rem` | Slightly larger than current `rounded-lg` for the larger card |
| Fallback (no backdrop-filter) | Ensure bg opacity is ≥ /70 | Opaque-enough bg if blur not supported | 4.78% of users have no support |

**Legibility guardrail (LAYOUT-02):** Body text on a glass card over the hero photo must pass WCAG AA (4.5:1 contrast ratio). With `bg-slate-950/50` and `text-slate-100`, the effective background is a mix of the photo and near-black — worst case is a bright photo region showing through. Setting `bg-slate-950/60` or adding an inner `bg-gradient` on the panel is the safety net if contrast fails the human-verify check.

**The existing data panel** already uses `bg-slate-950/30 backdrop-blur-md` — Phase 7 confirmed `text-slate-100` over this passes WCAG AA at 11.72:1–14.16:1 (from Phase 7 Plan 03 D-06 guardrail). For Phase 8.5, since the backdrop is now a photograph instead of the dark blurred backdrop, the panel opacity should increase to `/50`–`/60` to maintain that headroom.

**Example (complete glass panel wrapper):**

```jsx
// Source: pattern from epicweb.dev/tips/creating-glassmorphism-effects-with-tailwind-css
// Verified: Tailwind v3 backdrop-blur-* utilities exist at this version [VERIFIED: package.json 3.4.19]

<div className="relative z-10 backdrop-blur-md bg-slate-950/50 border border-slate-700/40 rounded-xl p-6 md:p-8 m-4 md:m-8">
```

### Pattern 4: Reusing `useScrollParallax` for Full-Background

**What:** The hook is unchanged. The caller passes `baseTransform: ''` instead of `'translateY(-50%)'`.

**Why the change is needed:** The Phase 8 hook composes `translateY(${py}px) ${baseTransform}`. The `baseTransform` was `'translateY(-50%)'` because the Phase 8 hero image used the `height: 200% / top: 50% / translateY(-50%)` manual center-crop trick. With `object-fit: cover`, there is no baseline transform to preserve — the image fills the container natively. Passing `''` leaves only `translateY(${py}px)` as the transform, which is correct for the full-background case.

```jsx
// Calling the hook for the full-background version:
const parallaxRef = useScrollParallax({
  speed: 0.05,
  disabled: reducedMotion,
  baseTransform: '',          // <-- changed from 'translateY(-50%)'
})
```

**Speed is unchanged:** At 0.05, scrolling 200px still produces ~10px displacement — the parallax is now *visible* because the image fills the screen rather than a contained box.

**Ref target:** Attach `parallaxRef` to the `<img>` element (not the outer container div). Same rule as Phase 8 — the ref must be on the element receiving `transform`, not the layout container.

### Pattern 5: `AtmosphericBackdrop` — Keep or Suppress?

**Context:** `AtmosphericBackdrop` is `position: fixed / z-0`. Once `BodyHero` is full-bleed, the backdrop layer is visible only where the hero does not cover it (e.g., areas above/below the hero, or if the hero has a transparent edge).

**Two valid paths (planner decides):**

| Option | What | Impact |
|--------|------|--------|
| A — Keep as depth layer | Leave as-is; it shows beneath the hero as a soft secondary depth plane | Minimal change; no regression; adds subtle visual depth for scroll positions where hero doesn't fill viewport |
| B — Hide under hero, show elsewhere | Set `AtmosphericBackdrop` opacity to 0 while a hero is visible, restore on scroll-past | More complex; requires scroll-aware logic; not recommended for this phase |
| C — Remove entirely | Delete `AtmosphericBackdrop` and `StarField` from App.jsx | Simplest; no depth layering; potentially stark for areas outside the hero |

**Recommendation:** Option A — keep `AtmosphericBackdrop` unchanged. It is behind the full-bleed hero and will only be visible in page regions the hero doesn't cover (extreme scroll, or header area). No code change required for the backdrop in this phase.

### Anti-Patterns to Avoid

- **`position: fixed` for the hero image:** Removes from flow; page has no height; scroll behavior breaks.
- **`height: 200%; top: 50%; transform: translateY(-50%)`** on the full-background `<img>`: This was the Phase 7/8 center-crop hack for a contained container. With `object-fit: cover`, this is unnecessary and will double-move the image.
- **Calling `useScrollParallax` with `baseTransform: 'translateY(-50%)'`** on the full-background image: The transform will fight `object-fit: cover` and produce a visually offset image.
- **`backdrop-filter` without a background color:** Blur alone with `bg-transparent` produces a floaty effect but no legibility improvement. Always pair with a semi-opaque background.
- **`bg-slate-950/30` (unchanged from Phase 7):** Adequate over the dark blurred backdrop, but may be too transparent over a bright photograph. Bump to `/50`–`/60` for the glass panel on a full-res image.
- **Omitting the `border` on the glass card:** Without a border, the glass card edge is invisible against a matching-color photo region. The border is a critical visual affordance.
- **Not including `-webkit-backdrop-filter` for older Safari:** While Safari 17+ no longer needs it, Safari 9–16 (still in use on older iOS devices) does. Add `-webkit-backdrop-filter: blur(12px)` alongside for belt-and-suspenders. [CITED: caniuse.com/css-backdrop-filter]

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Image overlay positioning | Custom `position: absolute` math with explicit px heights | CSS Grid single-cell stack | Grid auto-sizes to tallest child; no hardcoded heights needed |
| Frosted glass effect | Manual SVG filter or canvas blur | `backdrop-filter: blur()` (Tailwind `backdrop-blur-md`) | Browser-native GPU compositing; no JS involved |
| Background image blur | CSS `filter: blur()` on the image | `backdrop-filter: blur()` on the panel | `filter` blurs the element itself and everything around it; `backdrop-filter` blurs only what's behind the element |
| Parallax on full-background | New hook or library | `useScrollParallax` with `baseTransform: ''` | Hook is already written and tested; only the option value changes |
| Glassmorphism border | `box-shadow` tricks | `border border-slate-700/40` | Simpler; more explicit; consistent with existing Tailwind patterns in the codebase |

**Key insight:** The entire phase is a layout restructure + CSS value change. No new algorithms, no new dependencies, no new design primitives.

## Common Pitfalls

### Pitfall 1: baseTransform Not Updated for Full-Background Image

**What goes wrong:** `useScrollParallax` is called with `baseTransform: 'translateY(-50%)'` (the Phase 8 default). The full-background `<img>` has no `height: 200%` setup, so the `-50%` moves it to an unexpected vertical position. Hero image appears half-off-screen on first scroll tick.

**Why it happens:** Phase 8 hook default was designed for the 200%-tall center-crop hack in a contained container. That hack is removed in Phase 8.5.

**How to avoid:** Pass `baseTransform: ''` explicitly when calling `useScrollParallax` in the new `BodyHero`.

**Warning signs:** Hero image visibly jumps to wrong vertical position on first scroll event.

---

### Pitfall 2: Glass Panel Too Transparent Over Bright Photo

**What goes wrong:** `bg-slate-950/30` (the Phase 7 data panel value) was adequate over the dark blurred `AtmosphericBackdrop`. Over a full-res photo with bright regions (sky, surface highlights), the same opacity produces insufficient contrast for body text.

**Why it happens:** Phase 7's backdrop applied `brightness(35%)` CSS filter to the photo before it was visible. The full-bleed hero is the full-brightness photo — no filter treatment.

**How to avoid:** Use `bg-slate-950/50`–`/60` for the glass panel. Run the Phase 7 contrast guardrail at human-verify: compute or visually check text contrast over the brightest region of each body's photo.

**Warning signs:** Light gray card text (like labels and timestamps) fails to read over the hero image during human-verify.

---

### Pitfall 3: `position: absolute` Hero Causing Zero-Height Container

**What goes wrong:** If the hero image is positioned `absolute` within a wrapper div that has no explicit height, the wrapper collapses to zero height. The glass panel then renders at the top of the page with nothing behind it.

**Why it happens:** `position: absolute` removes an element from normal flow — the wrapper cannot size to it.

**How to avoid:** Use the CSS Grid single-cell pattern (the cell sizes to the tallest child — the panel). Or give the wrapper an explicit `min-height: 60vh` before using `position: absolute` for the hero.

**Warning signs:** Hero image appears to not render at all, or glass panel appears with a dark background (no photo visible behind it).

---

### Pitfall 4: `backdrop-filter` Not Activating on the Panel

**What goes wrong:** `backdrop-blur-md` class is present but the blur effect does not appear. The panel renders with an opaque background color but no frosted effect.

**Why it happens:** `backdrop-filter` only blurs the rendered content directly behind the element in the stacking context. If the hero image is not in the same stacking context (e.g., it is `position: fixed` at a different `z-index` than the panel's ancestor), the blur has nothing to apply to.

**How to avoid:** Ensure the hero image is visually behind the panel within the same stacking context. CSS Grid single-cell stacking guarantees this. Also: `backdrop-filter` requires the element's background to not be fully opaque (i.e., `bg-slate-950/50` not `bg-slate-950`).

**Warning signs:** Glass card shows solid dark background instead of frosted photo. Debug by temporarily setting `bg-transparent` — if blur appears, the background opacity was blocking it; if nothing appears, the stacking context is wrong.

---

### Pitfall 5: LQIP Visible on Body Already Loaded (Cross-Fade Layer Switch)

**What goes wrong:** After switching from Mars to Moon and back, the Mars LQIP placeholder briefly shows again before the full-res image reappears.

**Why it happens:** The full-background `<img>` may not be cached if the `<picture>` element was hidden at `opacity: 0` when the image loaded. Some browsers do not preload images that are not visible.

**How to avoid:** Preserve the per-body `loaded` state (`{ mars: false, moon: false }`) from Phase 8 — once a body's full-res image has loaded at least once, its LQIP remains hidden forever. The `loading="eager"` attribute on both body images ensures both start loading immediately regardless of which tab is active.

---

### Pitfall 6: Hero Overflow Bleed at Viewport Edges

**What goes wrong:** `backdrop-filter: blur()` (applied to the glass panel, not the hero) can have rendering artifacts at edges if the hero image extends to the browser edge. In this case the parallax `translateY` moves the image and can briefly expose the white/default page background behind it.

**Why it happens:** Parallax with `speed=0.05` at 200px scroll = 10px of displacement. The image must extend at least 10px beyond the container in all scroll directions.

**How to avoid:** Add a small amount of `scale(1.05)` to the hero image CSS, or ensure the container has `overflow: hidden`. The container should already have `overflow-hidden` (from Phase 7 on the wrapper) — confirm this is preserved in the new structure.

## Code Examples

### Full-Bleed BodyHero (restructured)

```jsx
// Source: pattern derived from Phase 8 BodyHero + object-fit cover + grid-area stacking
// baseTransform: '' is the critical change from Phase 8's 'translateY(-50%)'

import { useState } from 'react'
import marsWebp from '../assets/bodies/mars-1600.webp'
import marsPng from '../assets/bodies/mars-1600.png'
import moonWebp from '../assets/bodies/moon-1600.webp'
import moonPng from '../assets/bodies/moon-1600.png'
import { useScrollParallax } from '../hooks/useScrollParallax.js'

const LQIP = {
  mars: 'data:image/webp;base64,...', // unchanged from Phase 8
  moon: 'data:image/webp;base64,...', // unchanged from Phase 8
}
const HERO_ASSETS = {
  mars: { webp: marsWebp, png: marsPng, alt: 'Mars — NASA image' },
  moon: { webp: moonWebp, png: moonPng, alt: 'Moon — NASA image' },
}
const BODIES = ['mars', 'moon']

function BodyHero({ activeTab, reducedMotion }) {
  const [loaded, setLoaded] = useState({ mars: false, moon: false })
  // CHANGED: baseTransform '' — no center-crop hack; object-fit cover handles sizing
  const parallaxRef = useScrollParallax({ speed: 0.05, disabled: reducedMotion, baseTransform: '' })

  return (
    <div className="absolute inset-0 overflow-hidden" style={{ gridArea: '1 / 1' }}>
      {BODIES.map((body) => {
        const asset = HERO_ASSETS[body]
        const isActive = body === activeTab
        return (
          <div
            key={body}
            className="absolute inset-0"
            style={{ opacity: isActive ? 1 : 0, transition: reducedMotion ? 'none' : 'opacity 500ms ease' }}
          >
            <div
              className="absolute inset-0 bg-cover bg-center transition-opacity duration-300"
              style={{ backgroundImage: `url(${LQIP[body]})`, filter: 'blur(8px)', opacity: loaded[body] ? 0 : 1 }}
            />
            <picture>
              <source srcSet={asset.webp} type="image/webp" />
              <img
                ref={isActive ? parallaxRef : null}
                src={asset.png}
                alt={asset.alt}
                loading="eager"
                onLoad={() => setLoaded((prev) => ({ ...prev, [body]: true }))}
                className="absolute inset-0 w-full h-full object-cover object-center"
                style={{ willChange: 'transform' }}
              />
            </picture>
          </div>
        )
      })}
      <span className="absolute bottom-2 right-2 rounded bg-black/50 px-2 py-1 text-xs text-white" aria-label="NASA image">
        NASA image
      </span>
    </div>
  )
}

export default BodyHero
```

```jsx
    <TabBar activeTab={activeTab} onTabChange={setActiveTab} />
  </div>

  {/* CSS Grid single-cell: hero fills the cell, glass panel sits on top */}
  <div className="grid" style={{ gridTemplateColumns: '1fr' }}>
    {/* Hero: fills the grid cell behind the panel */}
    <BodyHero activeTab={activeTab} reducedMotion={reducedMotion} />

    {/* Glass panel: defines the cell height, sits above the hero */}
    <div
      className="relative z-10 backdrop-blur-md bg-slate-950/50 border border-slate-700/40 rounded-xl p-6 md:p-8"
      style={{ gridArea: '1 / 1' }}
    >
      {activeTab === TABS.MARS.id && <MarsTab />}
      {activeTab === TABS.MOON.id && <MoonTab />}
    </div>
  </div>
</main>
```

## Open Questions

1. **How tall should the full-bleed hero cell be?**
   - What we know: LAYOUT-01 says "fills the viewport" or "a significant portion of the viewport height." No specific value given.
   - What's unclear: Whether "fills the viewport" means `100vh` (full screen, data panel scrolled to), `min-height: 70vh` (hero prominent, panel visible without scrolling), or `min-height: 60vh`.
   - Recommendation: Use `min-height: 70vh` as a starting point — hero is cinematic and prominent, but the panel is visible below the fold without scrolling. Adjust at human-verify.

2. **Should the glass panel have rounded corners at the top too, or just bottom?**
   - What we know: Current data panel uses `rounded-lg`. The Phase 8.5 glass card floats over the hero — `rounded-xl` on all corners looks polished.
   - What's unclear: Whether the user prefers a fully rounded card or a card that meets the hero edge at the top.
   - Recommendation: `rounded-xl` on all corners. The card is positioned with `m-4 md:m-8` margin so it floats — corners should be visible all around.

3. **Should `AtmosphericBackdrop`'s filter be adjusted when the full-bleed hero is visible?**
   - What we know: Once the hero fills the viewport, the backdrop is mostly covered. Its only visible contribution is in page areas outside the hero.
   - What's unclear: Whether the bleed-through of the backdrop beneath the hero LQIP (before the full-res loads) looks good or creates a visual conflict.
   - Recommendation: Leave `AtmosphericBackdrop` unchanged for now. If LQIP-to-full-image transition looks odd at the edges, dial `brightness` lower or reduce the backdrop's opacity.

4. **Does the `parallaxRef` need to be on both the LQIP layer and the `<img>`, or only the `<img>`?**
   - What we know: Phase 8 attached the ref only to the `<img>`. The LQIP is a CSS background-image on a `div` — it cannot be `transform`-driven by a ref.
   - What's unclear: Whether the LQIP layer should also move with scroll.
   - Recommendation: Parallax ref on `<img>` only (same as Phase 8). The LQIP disappears within 1–2 seconds on a good connection; parallax mismatch during LQIP display is imperceptible.
