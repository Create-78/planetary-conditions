## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, NASA label pill (`px-2 py-1`) |
| sm | 8px | Compact element spacing, card internal label gaps |
| md | 16px | Default element spacing, glass panel padding on mobile (`p-6` = 24px, see exception) |
| lg | 24px | Glass panel padding mobile (`p-6`) |
| xl | 32px | Glass panel padding desktop (`p-8`) |
| 2xl | 48px | Major section breaks (header `mb-12`) |
| 3xl | 64px | Page-level spacing (not used directly in this phase) |

Exceptions:
- **Glass panel margin:** `m-4` (16px) on mobile, `m-8` (32px) on desktop — card floats above the hero with visible gap on all sides so rounded corners are exposed.
- **Hero min-height:** `min-height: 70vh` — this is a viewport-relative value, not a spacing token. Chosen so the hero is cinematic and prominent, with the top of the glass panel visible above the fold on a 1280px desktop without scrolling.
- **Bottom vignette height:** `h-1/3` (one-third of hero cell height) — retained from Phase 7 BodyHero for the soft gradient handoff at the base of the hero cell.

**Source:** RESEARCH.md Open Question #1 (70vh recommendation), existing App.jsx (`p-6 md:p-8`, `m-4 md:m-8` in pattern example).

### New in Phase 8.5 — Glass panel surface

The data panel changes from the Phase 7 dark-on-dark card to a glassmorphic overlay. The dominant color is the same `space-950` base but at higher opacity to compensate for the unfiltered photo background:

| Role | Value | Tailwind class | Notes |
|------|-------|----------------|-------|
| Glass panel background | `rgba(2, 6, 23, 0.50)` | `bg-slate-950/50` | Increased from `/30` (Phase 7 value) to `/50` — unfiltered photo behind requires higher opacity |
| Glass panel border | `rgba(51, 65, 85, 0.40)` | `border border-slate-700/40` | Defines card edge against photo regions; 40% opacity to remain subtle |
| Glass panel rounded corners | 12px | `rounded-xl` | Stepped up from `rounded-lg` — full-bleed floating card warrants larger radius |
| Backdrop blur | `blur(12px)` | `backdrop-blur-md` | Frosted-glass effect on the panel; blurs the hero photo visible behind the card |
| Fallback (no backdrop-filter) | `rgba(2, 6, 23, 0.70)` | `bg-slate-950/70` | 4.78% of users lack support; ensure bg opacity ≥ /70 as a fallback. Use CSS `@supports` or accept graceful degradation |

**Contrast guardrail (LAYOUT-02):** `text-slate-100` over `bg-slate-950/50` on a photo background. Phase 7 Plan 03 established 11.72:1–14.16:1 contrast headroom over the dark blurred backdrop at `/30`. With the panel at `/50` over an unfiltered photo, the effective composite is darker — contrast must be re-verified at human-verify checkpoint. If any label text fails WCAG AA (4.5:1) during human-verify, bump to `bg-slate-950/60` as the fallback.

**Source:** RESEARCH.md Pattern 3 (glass panel values), Pitfall 2 (opacity reasoning), STATE.md Phase 7 D-06 guardrail.

## Layout Contract

This section is Phase 8.5-specific. It defines the exact visual structure that replaces the current `BodyHero` + sibling data panel layout.

### Z-index stack (locked)

| Layer | Element | z-index | Position |
|-------|---------|---------|----------|
| 0 | `AtmosphericBackdrop` | `z-0` | `fixed` — kept unchanged (depth layer) |
| 0 | `StarField` | `z-0` | `fixed` — kept unchanged |
| 10 | `<main>` | `z-10` | `relative` — unchanged from Phase 7 |
| 0 (within grid cell) | `BodyHero` full-bleed layers | `[grid-area: 1/1]` | fills grid cell behind glass panel |
| 10 (within grid cell) | Glass data panel | `z-10` within grid cell | sits above hero in same grid cell |

**Source:** App.jsx (existing `relative z-10` on `<main>`), RESEARCH.md Architecture Patterns diagram, STATE.md Phase 1 Plan 2 (`StarField is fixed inset-0 z-0 pointer-events-none aria-hidden — content sits at z-10; this z-index contract is the baseline`).

### CSS Grid single-cell stack (locked)

Both the full-bleed hero and the glass data panel are placed in the same grid cell (`grid-area: '1 / 1'`). The grid cell auto-sizes to its tallest child (the glass panel). The hero fills the cell; the panel floats above it.

```
Wrapper div: grid (gridTemplateColumns: '1fr')
├── BodyHero: absolute inset-0, style={{ gridArea: '1 / 1' }}
│   └── min-height: 70vh (on the wrapper, not the hero element)
└── GlassPanel div: relative z-10, style={{ gridArea: '1 / 1' }}, alignSelf: 'end' (optional)
    └── backdrop-blur-md bg-slate-950/50 border border-slate-700/40 rounded-xl p-6 md:p-8 m-4 md:m-8
```

**Minimum height:** The grid wrapper gets `style={{ minHeight: '70vh' }}`. This ensures the hero is visually prominent even when the glass panel does not push the cell height high enough.

**Source:** RESEARCH.md Pattern 1 (CSS Grid single-cell), RESEARCH.md Code Examples (App.jsx Grid Stack).

### BodyHero image sizing (locked)

The Phase 7/8 center-crop hack (`height: 200%; top: 50%; transform: translateY(-50%)`) is **removed**. The `<img>` uses `object-fit: cover` to fill the container natively.

| Property | Phase 7/8 value | Phase 8.5 value | Rationale |
|----------|----------------|----------------|-----------|
| `<img>` height | `height: '200%'` | removed | `object-fit: cover` handles fill |
| `<img>` top | `top: '50%'` | removed | not needed with `object-fit: cover` |
| `<img>` transform (base) | `transform: 'translateY(-50%)'` | removed | not needed with `object-fit: cover` |
| `<img>` Tailwind | `absolute w-full object-cover object-center` | `absolute inset-0 w-full h-full object-cover object-center` | `inset-0 h-full` added to fill container explicitly |
| `parallaxRef baseTransform` | `'translateY(-50%)'` | `''` (empty string) | only `translateY(${py}px)` remains; no base offset needed |

**Source:** RESEARCH.md Pattern 2, Pitfall 1 (baseTransform), Anti-Patterns section.

### LQIP treatment (locked)

LQIP behavior is **preserved unchanged** from Phase 7:
- LQIP base64 strings are the same 24×13px WebP data URIs already in BodyHero.jsx
- LQIP layer: `absolute inset-0 bg-cover bg-center transition-opacity duration-300`, `filter: blur(8px)`
- LQIP fades to `opacity: 0` when its body's full-res image fires `onLoad`
- Per-body `loaded` state (`{ mars: false, moon: false }`) — once a body loads, its LQIP never shows again
- LQIP `transition-opacity duration-300` is intentionally NOT gated by `reducedMotion` — this is an image-loading concern, not a motion preference

**Source:** Phase 7 BodyHero.jsx (direct read), RESEARCH.md Pitfall 5.

### Bottom vignette (locked, optional review)

The Phase 7 bottom vignette (`absolute inset-x-0 bottom-0 h-1/3`, gradient `#020617 → transparent`) served as a soft handoff into the sibling data panel below. In Phase 8.5 the data panel is overlaid on the hero, not below it. The vignette MAY be removed or converted to a `rounded-xl` overflow mask. Planner should decide; both options are low-risk.

**Default if planner does not change:** Remove the vignette. The glass panel's rounded corners and backdrop blur provide the visual separation. If the hero-to-glass boundary looks harsh at human-verify, re-add `h-1/4` vignette.

### AtmosphericBackdrop (locked — keep unchanged)

`AtmosphericBackdrop` is kept as-is. It is `position: fixed z-0` and sits beneath the full-bleed hero. It provides subtle depth in page areas the hero does not cover (e.g., header region on scroll). No code changes. Filter values (`blur(24px) brightness(35%) saturate(80%)`) are retained.

**Source:** RESEARCH.md Pattern 5 (Option A), RESEARCH.md Assumptions Log A3.

### NASA honesty label (locked)

Retained from Phase 7: `absolute bottom-2 right-2 rounded bg-black/50 px-2 py-1 text-xs text-white`, `aria-label="NASA image"`. Positioned within the hero container div, which is inside the grid cell. No change needed.

**Source:** Phase 7 BodyHero.jsx (line 74).

## Motion & Interaction Contract

All motion behaviors are **inherited from Phase 8**. Phase 8.5 changes the mounting position of the animations (full-bleed vs. contained), not the animation logic itself.

| Behavior | Phase 8 implementation | Phase 8.5 change |
|----------|----------------------|----------------|
| Cross-fade on tab switch | `opacity: isActive ? 1 : 0`, `transition: 'opacity 500ms ease'` on each body layer | Unchanged — same cross-fade on full-bleed layers |
| Scroll parallax | `useScrollParallax({ speed: 0.05, disabled: reducedMotion, baseTransform: 'translateY(-50%)' })` | `baseTransform: ''` — only change |
| Reduced motion | `reducedMotion` prop from `usePrefersReducedMotion()` disables both cross-fade and parallax | Unchanged — prop flows through identically |
| LQIP blur-up | `transition-opacity duration-300` (not reduced-motion gated) | Unchanged |
| `AtmosphericBackdrop` cross-fade | Unchanged (Phase 8 wired it) | Unchanged |

**Parallax visibility improvement:** With a full-bleed image (fills viewport vs. contained 16:7 box), the existing `speed: 0.05` × scroll-distance = ~10px displacement becomes **visually prominent** without any hook change. This is the primary visual improvement of Phase 8.5 for MOTION-02.

**Source:** RESEARCH.md Pattern 4, STATE.md Phase 8 Plan 2 decision, existing BodyHero.jsx hook call.
